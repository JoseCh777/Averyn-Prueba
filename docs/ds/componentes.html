Hacer
  • Validar al salir del campo y al enviar; un mensaje por campo, junto al campo.
  • Tras un envío con error, mover el foco al primer campo inválido.
  • Reservar el espacio de la alerta para que el formulario no salte.
  • El botón de mostrar contraseña cambia el texto y aria-pressed, no la etiqueta.
No hacer
  • Marcar en rojo un campo que no falla (p. ej. la contraseña cuando solo el correo es inválido).
  • Placeholder como única etiqueta. Bordes de campo con el hairline (2.5:1).
  • Mensajes genéricos ("Error", "Inválido") sin decir cómo arreglarlo.

Campo de búsqueda

Para filtrar una lista que ya está en pantalla. Filtra mientras se escribe, dice cuántos resultados hay y se limpia con un botón o con Esc. El atajo / lo enfoca desde cualquier parte de la página.

/

    Teclado

    • / enfoca el campo (si no estás escribiendo en otro).
    • Esc limpia el texto; con el campo vacío, quita el foco.

    Reglas

    • type="search" con etiqueta oculta para lectores de pantalla (el icono no es una etiqueta).
    • El conteo se anuncia con role="status": "3 resultados" o "Sin resultados para «x»".
    • El botón de limpiar solo aparece con texto y mide 44 px.
    • Sin resultados: ofrecer cómo salir ("Quita algún filtro"), no una lista vacía.

    Código de un solo uso (6 dígitos)

    Para confirmar el correo o el segundo factor. Seis casillas que se comportan como un solo campo: avanzan solas, aceptan pegar el código completo y avisan sin culpar si falla. Es el mismo código que prometen los correos de verificación.

    Código de verificación
    Escribe los 6 dígitos que enviamos a ana@ejemplo.edu. En esta demo el código correcto es 482913.

    Teclado

    • Cada dígito avanza a la siguiente casilla; Retroceso en una casilla vacía vuelve a la anterior.
    • ← → se mueven entre casillas; Inicio/Fin saltan a la primera y a la última.
    • Pegar (Ctrl+V) reparte los dígitos; se ignoran espacios y guiones.

    Reglas

    • inputmode="numeric" y autocomplete="one-time-code" para que el móvil sugiera el código del SMS o del correo.
    • Un fieldset con legend; cada casilla tiene su etiqueta ("Dígito 3 de 6").
    • Al completarse, se verifica sola; el botón existe para quien no confía en la automatización.
    • Error: borde rojo y texto ("Código incorrecto. Te quedan 2 intentos."). Tras 3 fallos, se bloquea con el motivo y cuándo se puede reintentar.
    • "Reenviar" se activa tras una espera visible; nunca se dice si el correo existe.

    Copy aprobado

    • Error: "Código incorrecto. Te quedan 2 intentos."
    • Bloqueo: "Demasiados intentos. Vuelve a intentarlo en 5 minutos."
    • Éxito: "Correo confirmado."

    Contraseña con indicador de fuerza

    Muestra qué se pide antes de escribir y cómo va la contraseña mientras se escribe: una barra de cuatro tramos, una palabra y una lista de requisitos con icono. El color nunca es el único aviso.

    Escribe una contraseña.

      Reglas

      • Los requisitos se ven desde el principio, no como regaño tras el primer error.
      • Cada requisito lleva icono y estado en texto ("cumplido" / "falta") para lectores de pantalla.
      • La barra tiene 4 tramos y una palabra: Muy débil, Débil, Buena, Fuerte. La palabra se anuncia de forma educada (aria-live="polite").
      • Mostrar/Ocultar es un botón con aria-pressed; nunca se deshabilita pegar.
      • autocomplete="new-password" para que el gestor de contraseñas proponga una.
      • Mínimo 10 caracteres; sin tope máximo menor a 64.

      Importante

      La fuerza de esta demo es una estimación simple. En producción la validación definitiva (y la lista de contraseñas filtradas) la hace el servidor.

      Selector de fechas y rangos

      Para filtrar gráficos, bitácoras y reportes. Atajos a la izquierda para lo habitual (hoy, 7 días, 30 días, trimestre) y un calendario para el rango exacto. No se pueden elegir fechas futuras: no hay datos de lo que aún no pasó.

      Elige la fecha inicial.

      Teclado

      • ← → día · ↑ ↓ semana
      • Inicio / Fin primer y último día de la semana
      • RePág / AvPág mes anterior y siguiente
      • Enter o Espacio marca el inicio y luego el fin
      • Esc cierra y devuelve el foco al botón

      Reglas

      • El botón muestra el periodo vigente en texto ("1 sep – 30 sep 2026"), no solo "Personalizado".
      • Los atajos aplican al instante; el rango manual necesita "Aplicar".
      • Fechas futuras deshabilitadas con aria-disabled y en gris claro, no ocultas.
      • Días de 40 px y rejilla con role="grid"; el rango se dice en texto bajo el calendario.
      • Semana desde lunes. Formato es-PE.

      Combobox con autocompletar

      Para elegir un valor de una lista larga (instituciones, personas, dispositivos). Se escribe para filtrar; el texto coincidente se resalta y el lector de pantalla anuncia cuántos resultados hay.

        Usa las flechas para recorrer y Enter para elegir.

        Teclado

        • ↓ ↑ mueven la opción activa (aria-activedescendant); el foco se queda en el campo.
        • Enter elige · Esc cierra, y una segunda vez limpia el texto.

        Reglas

        • Roles ARIA 1.2: combobox + listbox + option.
        • Opciones de 44 px; el texto buscado en azul y negrita, no solo con fondo.
        • Sin resultados: "Sin resultados para «x»", nunca una lista vacía.
        • Para menos de 7 opciones, usa un <select> (hz-select).

        Multi-select y filtros activos

        Para elegir varios valores de una lista (dispositivos, estados, instituciones). Lo elegido se ve como chips que se quitan uno a uno, y los filtros activos quedan resumidos sobre la tabla con una salida clara: "Limpiar filtros".

          Usa las flechas y Espacio o Enter para marcar. Retroceso quita el último.
          Filtros

          Teclado

          • ↓ ↑ mueven la opción activa; Espacio o Enter marcan o desmarcan y mantienen abierta la lista.
          • Retroceso con el campo vacío quita el último chip; Esc cierra la lista.
          • Cada chip es un botón (Tab, Enter o Supr lo quitan).

          Reglas

          • listbox con aria-multiselectable="true" y opciones con aria-selected; la marca es un check más el texto.
          • Cada chip es un botón que dice "Quitar CAM-001" (aria-label), con área de 28 px dentro de una píldora de 32 px (mínimo 24 px en WCAG 2.2); no es solo un ✕ sin nombre.
          • Los filtros activos viven en una fila propia sobre los resultados, con el conteo ("5 eventos") y "Limpiar filtros".
          • Más de 5 chips: se resumen ("+3 más") con su detalle en el tooltip.
          Componentes · Acciones y formularios

          Validación de formularios y resumen de errores

          Cuándo avisar y cómo. Se valida al salir del campo (no mientras se escribe por primera vez) y de nuevo al enviar. Si hay errores, una alerta arriba los resume con enlaces a cada campo y recibe el foco.

          Corrige 2 campos para continuar

            Cuándo validar

            • Al salir del campo (blur), solo si la persona ya lo tocó; así no se grita al empezar.
            • Una vez inválido, revalida mientras escribe para que el error desaparezca en cuanto se corrige.
            • Al enviar, valida todo, muestra el resumen y mueve el foco a él.

            Reglas

            • Error en el campo: borde rojo, icono, texto bajo el campo (aria-describedby) y aria-invalid="true".
            • Resumen: role="alert", tabindex="-1" para recibir el foco, y enlaces que llevan al campo.
            • El mensaje dice qué hacer ("Escribe un correo como nombre@dominio.com"), no solo qué está mal.
            • Nunca se vacía un formulario por un error; nunca se deshabilita el botón de enviar como única señal.

            Copy aprobado

            • Resumen: "Corrige 2 campos para continuar."
            • Nombre: "Escribe el nombre completo."
            • Correo: "Escribe un correo como nombre@dominio.com."
            • Documento: "El documento tiene 8 dígitos."

              Píldoras de estado 3 variantes

              Suave · por defecto

              Fondo tintado y texto del tono, sin borde. Es la que se usa en tablas y listas: se lee de un vistazo y no compite con los datos.

              Contorno

              Borde y texto del tono, sin relleno. Para estados secundarios: borrador, "Sin dispositivo", etiquetas dentro de una tarjeta ya coloreada.

              Sólida

              Fondo del tono y texto blanco. Para énfasis puntual: un contador, "Nueva", un estado crítico. Nunca más de una por fila.

              Reglas. Una sola variante por tabla. Sin punto: el estado lo dice la palabra; el icono es opcional, decorativo (aria-hidden) y siempre el mismo para el mismo estado. Contraste del texto ≥ 5:1: sobre el fondo suave (los tonos -strong de Éxito y Aviso lo garantizan), blanco sobre el tono -text en la sólida y tono sobre blanco en el contorno. La píldora no es interactiva; si lo fuera, sería un botón.

              Tabla avanzada

              Para listas de personas, dispositivos o eventos con las que se trabaja: búsqueda, orden, selección, acciones masivas, densidad y paginación. Misma línea fina de 1 px del resto del sistema.

              Estado

              Anatomía

              1. Barra: búsqueda a la izquierda, densidad a la derecha. Al seleccionar filas se reemplaza por la barra de acciones masivas con el conteo.
              2. Cabecera: columnas ordenables como botones con aria-sort; flecha azul en la activa.
              3. Filas de 60 px (cómoda) o 44 px (compacta), con casilla de 44 px de área.

              • La casilla de cabecera selecciona solo la página visible y queda "indeterminada" si hay parcial.

              • Sin resultados: una fila con mensaje y cómo limpiar el filtro.
              • Las acciones masivas destructivas piden confirmación.

                Paleta de comandos Ctrl K

                Un acceso rápido a cualquier pantalla o acción escribiendo. Complementa la navegación, no la reemplaza. Lo que aún no existe aparece como "Próximamente" y no se puede abrir, igual que en el dock.

                  • Sin resultados: "Nada coincide con «x»".
